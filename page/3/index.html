HttpServlet

在请求处理类继承了HttpServlet的时候，可以重写doPost和doGet两个函数，他们分别有HttpServletRequest request和HttpServletResponse response两个参数

request可以做的事如下：

方法 作用 登录场景示例
setCharacterEncoding("UTF-8") 设置请求编码（解决中文参数乱码，必须放在获取参数之前） request.setCharacterEncoding("UTF-8");
getParameter("参数名") 获取前端传的单个参数（POST/GET 都能用） String username = request.getParameter("username");
getParameterMap() 获取所有参数（返回Map<String, String[]>，适合多值参数如复选框） 登录场景用不到，注册/表单场景常用
getHeader("请求头名") 获取请求头（如Token、Content-Type） String token = request.getHeader("token");
setAttribute("key", value) 往请求域存数据（仅转发时有效） request.setAttribute("msg", "登录失败");
getRequestDispatcher("路径") 请求转发（跳转到其他页面/Servlet，服务器内部跳转） 登录失败转发回登录页

response的操作：

方法 作用 登录场景示例
setCharacterEncoding("UTF-8") 设置响应编码（解决返回中文乱码） response.setCharacterEncoding("UTF-8");
setContentType("类型") 设置响应类型（如 HTML/JSON，同时会指定编码） response.setContentType("application/json;charset=UTF-8");
getWriter().write("内容") 给前端返回字符串/JSON数据（最常用） writer.write("{/"code/":200,/"msg/":/"登录成功/"}");
sendRedirect("路径") 重定向（客户端跳转，如登录成功跳首页） response.sendRedirect("/home.html");
setHeader("头名", "值") 设置响应头（如跨域、缓存） response.setHeader("Access-Control-Allow-Origin", "*");

setTimeout

setTimeout 是 JavaScript 中的一个全局函数（实际上是 window.setTimeout），用于在指定的延迟时间（毫秒）后，执行一次指定的函数或代码段。它是实现异步编程、延迟执行和定时任务**的核心工具。

  1. 基本语法
  1. 关键行为与注意事项

    1. 只执行一次：与 setInterval（重复执行）不同，setTimeout 在延迟结束后只执行一次回调。若需重复执行，通常需要在回调函数内部递归****调用 setTimeout。

    2. 延迟不绝对精确：实际的执行时间可能晚于设定的 delay。因为如果主线程正忙于执行其他同步任务（如长循环、复杂计算），事件队列中的回调就必须排队等待。

    3. this 指向问题：在普通函数形式的回调中，this 通常会丢失其原始上下文，而指向全局对象（浏览器中是 window）或 undefined（严格模式）。解决方法有：

      • 使用箭头函数（推荐）：setTimeout(() => { this.doSomething() }, 1000)

      • 在外部保存 this：const self = this; setTimeout(function() { self.doSomething() }, 1000)

      • 使用 bind：setTimeout(this.doSomething.bind(this), 1000)

    4. 最小延迟限制：浏览器有最小延迟时间限制（通常为 4ms），嵌套调用的 setTimeout 延迟会被强制增加。

﻿# 数据库学习笔记

1. 什么是数据库？

  • 数据库：DataBase（DB），是存储和管理数据的仓库

  • 数据库管理系统：DataBase Managerment System(DBMS)，操纵和管理数据库的软件

  • SQL：Structured Query Language，操作关系型数据库的编程语言，定义了一套操作关系型数据库统一标准（开发人员发送语句修改数据库就是SQL语句）

2. MySQL概述

2.1 安装

社区版下载地址：https://downloads.mysql.com/archives/community/

安装指南：MySQL安装文档

2.2 MySQL连接

  • 语法：mysql [-h数据库服务器IP地址 -p端口号] -u用户名 -p密码

    • 例如：mysql -uroot -p123

    • 端口号和IP地址不指定默认是：本机的3306端口

    • 如果需要隐藏输入的密码，可以在输出完-p时直接回车，密码就会以*显示

  • 企业中的数据库一般是部署在机房的，使用的时候就需要指定 IP和端口号远程访问了

  • 关系型数据库：建立在关系模型基础上，由多张相互连接的二维表组成的数据库

  • 特点：

    • 使用表存储数据，格式统一，便于维护

  • 预编译SQL（参数动态传递）

预编译的SQL，也是在项目开发中推荐使用的SQL语句。主要的作用有两个：

  • 防止SQL注入

  • 性能更高

5. 事务

在交易系统的转账操作中，我们可能遇到一个人的钱被扣了但是另外一个人的钱没有增加，此时就需要使用事务，来让操作回滚

5.1 事务操作

  • 查看/设置事务提交方式

    • SELECT @@autocommit;

    • SET @@autocommit=0;

  • 提交事务

    • COMMIT;

  • 回滚

    • ROLLBACK;

  • 开启事务

    • START TRANSACTION 或 BEGIN

5.2 事务四大特性

  • 原子性（Atomicity）：事务是不可分割的最小操作单元，要么全部成功，要么全部失败。

  • 一致性（Consistency）：事务完成时，必须使所有的数据都保持一致状态。

  • 隔离性（Isolation）：数据库系统提供的隔离机制，保证事务在不受外部并发操作影响的独立环境下运行。

    • 也就是两个相同的事务不会互相影响

  • 持久性（Durability）：事务一旦提交或回滚，它对数据库中的数据的改变就是永久的。

5.3 并发事务问题

  • 脏读：一个事务读到另外一个事务还没有提交的数据

  • 不可重复读：一个事务先后读取同一条记录，但两次读取的数据不同，称之为不可重复读

  • 幻读：一个事务按照条件查询数据时，没有对应的数据行，但是在插入数据时，又发现这行数据已经存在，好像出现了“幻影”

5.4 事务隔离级别

  • 查看事务隔离级别

      SELECT @@TRANSACTION_ISOLATION;

  • 设置事务隔离级别

SET [SESSION|GLOBAL] TRANSACTION ISOLATION LEVEL {READ UNCOMMITTED | READ COMMITTED | REPEATABLE READ | SERIALIZABLE}

这里的SESSION和GLOBAL区别在于：

  • SESSION只对当前数据库连接会话使用

  • GLOBAL对所有新创建的会话有效，重启MySQL数据库失效

﻿# 鉴权机制

鉴权：也就是判断用户是否有访问特定接口的权限

例子：

  • 用户未登录时，无法访问登录后才能访问的接口

  • 普通用户，无法访问管理员才能访问的接口

在这些情况下，我们都需要判断用户是否具有相关的权限，从而保护服务器和数据库的安全

其中，相关的技术有：Cookie，Session，Token 三种

1. HTTP 协议深入了解

HTTP 协议：是超文本传输协议，主要用于浏览器和服务器之间交互数据，其中交互分为请求和响应

1.2 HTTP 协议的特点

特点如下：

  • 简单快捷
  • 无连接无状态
    • 无连接无状态的意思是：多个请求之间是没有关联的，相互独立

这种无连接无状态的形式就导致了开发麻烦，因此就有了 Cookie 这个技术

2. Cookie 以及 Cookie 鉴权原理

想要了解 Cookie 是怎么鉴权的，首先需要明白 Cookie 是什么

2.1 什么是 Cookie ？

Cookie 是服务器产生的，保存在客户端的一小段文本信息，格式是key:value，也就是键值对

Cookie 分为两类：

  • 会话级 Cookie：保存在浏览器内存中，关闭会话后 Cookie 会自动丢失
  • 持久化 Cookie：保存在硬盘中，只有到达了失效时间才会失效

2.2 怎么查看 Cookie ？

既然 Cookie 在日常的网页使用中经常存在，那么 Cookie 如何查看呢？

步骤：点开网页，F12 打开开发者工具，选择 application（应用程序），找到 Cookie 选项并选择一个链接即可

名词解释：

  • 名称：Cookie 的名称
  • 值：Cookie 携带的值
  • Domain：范围，访问这个域名就会携带这个 Cookie
  • Path：路径，访问这个路径就会携带这个 Cookie
  • Expires / Max-Age：存活时间
    • 会话代表会话 Cookie，关闭会话后失效
    • 否则是截止日期，过期后才失效
  • 大小：Cookie 的大小

除了直接在开发者工具查看，也可以在浏览器设置找到 Cookie 相关选项查看所有的 Cookie

2.3 Cookie 鉴权的原理

Cookie 鉴权的步骤：

  1. 第一次访问网站时，服务器通过响应头里面的 Set-Cookie 字段给客户端响应 Cookie 并保存
  2. 以后访问网站时，请求中的请求头都会带上这些 Cookie，实现鉴权

2.4 Cookie 的缺点

需要注意的是：Cookie 由于可以被直接查看，所以存储的都是一些不重要的数据

3. Session 以及 Session 鉴权的原理

Session 也是保存在浏览器的一个字符串，并且是通过 Cookie 实现的

3.1 Session 的鉴权原理

Session 在浏览器保存的步骤和 Cookie 很类似：

  1. 第一次登录后，服务器通过 Set-Cookie 这个字段返回 SessionId，并且通过 Cookie 保存在浏览器
  2. 后续操作时，同样会携带这个 SessionId 在请求头中，实现鉴权

需要注意：Session 在 Cookie 中保存都是会话级别的，默认的生命周期是半个小时

3.2 Session 的缺点

SessionId 同时保存在服务器中，非常占用服务器的内存

4. Token 以及 Token 的鉴权原理

4.1 Token 的鉴权原理

  1. 登录后，服务器生成 Token 或者通过独立的接口生成 Token，然后存储在服务器的硬盘或者数据库里
  2. 以后的操作带来的请求，必须在请求头或者请求参数里面带上 Token 实现鉴权

Token 一般是经过加密，并且具有生命周期的，一般有两类：

  • access_token：生命周期在15分钟到2小时之间
  • refresh_token：生命周期是15天
