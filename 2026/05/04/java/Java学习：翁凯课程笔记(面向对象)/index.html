封闭和开放

封闭的成员属性

使用private关键字，可以使得成员变量和成员函数的访问属性变成私有的

对于私有的成员变量或者成员函数，只有两种访问方式：

  • 同一个类中的成员函数（包括main函数）

  • 同一个类中变量初始化的地方

需要注意的是：私有是针对类而不是对象！

所以，对于不同的对象，只要他们是一个类的，就可以互相访问对方的私有成员

对象数组

  • 当我们新建了一个int类型的数组的时候，我们想要输出一个元素的值，输出了0

  • 但是当我们新建了一个String数组的时候，我们想要输出一个元素的值，却输出了null

    • 这是因为String数组当中的每一个元素都是一个管理者，而非String本身

    • 没有给String数组中元素分配东西的时候，没有指向任何东西，所以使用length()会报错

    • 所以我们定义了一个String类型的变量并初始化为null的时候，使用length()会报错

所以说我们使用的String数组就是一个对象数组，分配了多个管理者，在没有被赋值时，这些管理者的值就是null，此时不能使用.length()操作

用一句话来说就是：对象数组中的每个元素都是对象的管理者而非对象本身

子类和父类

如何创建

我们如果需要创建两个类，分别是CD和DVD，存储一些信息的时候，很容易发现这两者的代码有高度重复性，为了解决这个问题，Java拥有了子类和父类这两个概念

父类Item直接使用普通的类定义即可

子类的定义只需要在定义后面加上extends 父类名称即可

继承

在子类定义之后，子类就继承了父类的东西，此外子类还可以自己添加新的东西到子类当中

  • 所谓的继承就是拥有了父类的成员变量和成员函数

    • 但是需要注意的是无法继承父类中用private关键字修饰的成员变量或者函数

    • 如果使用protected，子类和同包可访问

对于子类自己定义的接口或者变量，子类自行初始化

对于继承来的父类的变量，子类可以通过super()函数传入接收到的值并利用父类中的构造方法进行初始化

顺序

子类的初始化一定遵循：

  • 先进行父类变量的初始化和构造函数

  • 在进行子类变量的初始化和构造函数

子类和父类的关系

  • 子类可以继承得到父类的所有东西

    • 但是private的东西子类不能直接使用，需要使用super()函数调用父类中对应的构造函数

  • 子类中如果有和父类中同名的变量，则在子类里面操作时，默认操作的是子类自己的那个变量

    • 如果子类和父类都有title这个变量

    • 子类中的this.title指的是子类自己的，父类中的this.title指的是父类中的

  • 同样的，如果子类和父类都拥有同名函数

    • 默认会调用子类中的函数

    • 需要使用super.函数名来调用父类中的函数

多态变量

首先需要明确的是，在Java当中

  • 类定义了类型

  • 子类定义了子类型

  • 子类的对象可以被当作父类的对象来使用

    • 赋值给父类的变量

    • 传递给需要父类对象的函数

    • 放进存放父类对象的容器里

也就是说

  • Java的对象变量是多态的，他们能保存不止一种类型的对象

  • 它们可以保存声明类型的对象，也可以保存声明类型的子类的对象

  • 当把子类的对象赋给父类的变量的时候，就发生了向上造型

抽象

抽象函数

指的是表达概念而无法实现具体代码的函数

抽象类

表达概念而无法构造出实体的类

特性

  • 带有abstract关键字的函数或者类

  • 有抽象函数的类一定是抽象类（为了防止误用抽象函数）

    • 但是抽象类也可以有非抽象函数，并且可以继承给子类

  • 抽象类不能制造对象，但是可以定义变量

    • 任何继承了抽象类的非抽象类的对象可以赋给这个变量

  • 继承自抽象类的子类必须覆盖父类的抽象函数（否则可能导致抽象函数被运行）

    • 否则自己也成为一个抽象类（因为继承了父类的抽象函数）

接口

  • 接口是纯抽象类

    • 所有的成员函数都是抽象函数

    • 所有的成员变量都是public static final

  • 接口规定了长什么样，但是不管里面有什么

实现方式

  • 把正常的类里面的class换成interface

    • interface是一种特殊的class

  • 接着在里面添加声明函数

    • 注意这里面的函数不需要实现，因此不存在{}

    • 在Swing中，一旦出现大量的按钮控件，就需要非常多的类来记录每个按钮按下来的响应机制

    • 而有了匿名类，我们只需要重写这个接口的函数就可以了，不需要再新建一个类

异常捕捉时的匹配

异常捕捉的时候也存在子类和父类的关系

  • 既然异常是一个类，那么自然存在一个类似于Object这样的类

  • 这个所有异常类的父类就是Exception类，当然Exception类也继承了Throwable

  • 在我们自定义异常类的时候，也可以让一个自定义异常类变成其他自定义异常类的子类

    • 这个时候我们只要使用一个父类来捕捉

    • 所有的子类也会被捕捉

比如说：

我们让CloseException成为OpenException的子类，那么即使抛出一个CloseException的异常，也可以被OpenException接收

  • 需要注意的是

    • catch是从上往下执行的，不断地寻找是否有匹配的异常

    • 所以如果父类在上，子类在下，编译器是不允许的，因为子类的异常捕捉不到任何异常

    • 同样的，如果子类在上，父类在下，那么这个子类的异常就会先被这个子类所在catch语句捕捉

  • 类似于ArrayIndexOutOfBoundsException这种数组越界的异常不需要写在函数的throws

    • 这类异常是系统的异常，并不属于受检异常

    • 如果都要加在函数后面就会有一大堆了

    • 当然这种异常我们也可以使用catch(Exception e)来捕捉

当异常遇到继承

我们有两个规则

  • 第一点

    • 当我们new出一个子类对象并赋给一个父类变量的时候，这是没有问题的

    • 假如说子类重写父类的一个函数，并尝试抛出更多的异常

    • 我们拿这个父类变量（实际上是子类对象）调用这个函数的时候，编译器只会检查父类抛出的异常是否解决，而完全不知道这个子类对象还会抛出更多的异常，这样就可能导致异常没有被捕捉到

    • 当然我们可以在子类新建一个新的、父类没有的函数的时候，声明可能抛出的新的异常

  • 第二点

    • 在子类的构造函数调用的时候，必定会调用到父类的构造函数

    • 这个时候假如说父类的构造函数抛出了一个异常，而子类的构造函数又声明这个异常，这就可能导致这个异常无法被捕捉

    • 所以必须声明父类构造函数中声明的所有异常，当然也可以声明新的异常
