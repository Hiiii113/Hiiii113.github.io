init和defer函数

init函数

init()是一个特殊的函数，存在以下特性：

  1. 不能被其他函数调用，而是自动在 main 函数前被调用
  2. init 函数不能作为参数传入
  3. 不能有传入参数和返回值
  4. 一个 go 文件下可以有多个init()，谁在前就先执行谁

defer函数

defer 函数其实就是把语句注册，底层是压入一个栈，然后在即将 return 的时候拿出来执行

因为这些调用直到 return 前才被执行，因此可以用来做资源清理

自定义类型和类型别名

自定义类型

在 Go 语言中，自定义类型指的是使用 type 关键字定义的新类型，它可以是基本类型的别名，也可以是结构体、函数等组合而成的新类型

其实结构体就是自定义类型的一种

比如：对基础类型 int 自定义一个类型

类型别名

和自定义类型很像，但是存在以下不同：

  1. 不能绑定方法
  2. 类型实际上还是原来类型
  3. 和原始类型比较不需要转化

接口

接口是一组仅包含方法名、参数、返回值的未具体实现的方法的集合

如果学习过 Java，接口就是 interface，但是有一点不同：

不需要指定一个结构体实现了另外一个结构体，只要完成了所有方法，自动实现

注意：

接口本身不能绑定方法，接口是值类型，保存的是：值+原始类型

比如 animal 存的就是原始类型（Chicken）和里面的值（”ikun”）

类型断言

在使用接口的时候，可以使用类型断言获取类型

或者断言某个类型

空接口

空接口是一个特殊的类型，用interface()表示，可以接收任何类型

用途：

  1. 用于变量，可以接收任何类型
  2. 用于函数参数，可以接收任何类型

协程

Goroutine 是 Go 运行时管理的轻量级线程

在 Go 里面，开启一个协程非常简单

如果把主线程最后的time.Sleep(2 * time.Second)去掉，程序就会没有任何输出

这是因为主线程停止了，所有协程也会停止

协程的原理是这样的：代码运行到协程语句后，立马将这个协程放在后台跑，不干扰其他线程

如果主线程结束，其他协程也会结束

WiatGroup

但是，我们无法预知协程何时完成，所以我们可以用等待组实现主线程等待协程跑完再行动

这里的sync.WaitGroup{}里面存的就是一个计数器

  • wait.Add()：就是指明有多少个要等，里面的 count 也变成这个
  • wait.Done()：一个协程跑完，count–
  • wait.Wait()：等待直到count == 0

这里使用的是全局的等待组，所有的函数都共用这个等待组

规范的项目开发里面一般不这样写，而是给协程函数传入这个等待组（注意传的是指针）

线程安全

什么是线程安全？

假如有两个协程，一个对一个全局变量++，一个对全局变量–，这个时候你会发现结果是不确定的

这是因为两个协程同时进行，导致了相互干扰

同步锁

为了解决这个问题，我们可以给操作加锁

给每一次的 num 操作都先加锁，运行完再解锁，实现了同步锁

异常处理

在 Go 语言里面，由于没有异常捕获，所以导致每一次调用函数都要手动接一下 err

常见的异常处理方式有很多

中断程序

当遇到某些异常的时候，我们无法进行后续操作，此时会直接终止程序

恢复程序

使用了 panic 函数之后，整个程序都会立即停止，但是仍然会执行 defer

所以我们可以在 defer 中对 panic 进行捕获，让程序至少不会崩溃
