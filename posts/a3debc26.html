﻿# 前后端交互笔记

HttpServlet

在请求处理类继承了HttpServlet的时候，可以重写doPost和doGet两个函数，他们分别有HttpServletRequest request和HttpServletResponse response两个参数

request可以做的事如下：

方法 作用 登录场景示例
setCharacterEncoding("UTF-8") 设置请求编码（解决中文参数乱码，必须放在获取参数之前） request.setCharacterEncoding("UTF-8");
getParameter("参数名") 获取前端传的单个参数（POST/GET 都能用） String username = request.getParameter("username");
getParameterMap() 获取所有参数（返回Map<String, String[]>，适合多值参数如复选框） 登录场景用不到，注册/表单场景常用
getHeader("请求头名") 获取请求头（如Token、Content-Type） String token = request.getHeader("token");
setAttribute("key", value) 往请求域存数据（仅转发时有效） request.setAttribute("msg", "登录失败");
getRequestDispatcher("路径") 请求转发（跳转到其他页面/Servlet，服务器内部跳转） 登录失败转发回登录页

response的操作：

方法 作用 登录场景示例
setCharacterEncoding("UTF-8") 设置响应编码（解决返回中文乱码） response.setCharacterEncoding("UTF-8");
setContentType("类型") 设置响应类型（如 HTML/JSON，同时会指定编码） response.setContentType("application/json;charset=UTF-8");
getWriter().write("内容") 给前端返回字符串/JSON数据（最常用） writer.write("{/"code/":200,/"msg/":/"登录成功/"}");
sendRedirect("路径") 重定向（客户端跳转，如登录成功跳首页） response.sendRedirect("/home.html");
setHeader("头名", "值") 设置响应头（如跨域、缓存） response.setHeader("Access-Control-Allow-Origin", "*");

setTimeout

setTimeout 是 JavaScript 中的一个全局函数（实际上是 window.setTimeout），用于在指定的延迟时间（毫秒）后，执行一次指定的函数或代码段。它是实现异步编程、延迟执行和定时任务**的核心工具。

  1. 基本语法
  1. 关键行为与注意事项

    1. 只执行一次：与 setInterval（重复执行）不同，setTimeout 在延迟结束后只执行一次回调。若需重复执行，通常需要在回调函数内部递归****调用 setTimeout。

    2. 延迟不绝对精确：实际的执行时间可能晚于设定的 delay。因为如果主线程正忙于执行其他同步任务（如长循环、复杂计算），事件队列中的回调就必须排队等待。

    3. this 指向问题：在普通函数形式的回调中，this 通常会丢失其原始上下文，而指向全局对象（浏览器中是 window）或 undefined（严格模式）。解决方法有：

      • 使用箭头函数（推荐）：setTimeout(() => { this.doSomething() }, 1000)

      • 在外部保存 this：const self = this; setTimeout(function() { self.doSomething() }, 1000)

      • 使用 bind：setTimeout(this.doSomething.bind(this), 1000)

    4. 最小延迟限制：浏览器有最小延迟时间限制（通常为 4ms），嵌套调用的 setTimeout 延迟会被强制增加。

常用的错误码

分类 状态码 名称 含义 典型使用场景
成功 ==200== OK 请求成功 登录成功、查询数据、提交表单正常完成。
==201== Created 资源创建成功 用户注册成功、新建文章成功。
==204== No Content 成功但无内容 删除操作成功，无需返回数据。
客户端错误 ==400== Bad Request 请求参数错误 JSON 格式错误、必填项缺失、数据类型不对。
401 Unauthorized 未授权/未登录 Token 过期、未携带 Token、密码错误(严格模式)。
403 Forbidden 禁止访问 已登录但权限不足（如普通用户访问管理员接口）。
==404== Not Found 资源不存在 请求的 URL 错误、查询的数据 ID 不存在。
405 Method Not Allowed 方法不允许 用 GET 请求了只支持 POST 的接口。
==409== Conflict 资源冲突 注册用户时用户名已存在。
429 Too Many Requests 请求过于频繁 触发限流、验证码尝试次数过多。
服务器错误 ==500== Internal Server Error 服务器内部错误 代码抛出异常、数据库连接失败、空指针。
502 Bad Gateway 网关错误 后端服务挂了，Nginx 连不上。
503 Service Unavailable 服务不可用 服务器维护中、负载过高。
504 Gateway Timeout 网关超时 后端处理时间过长，超过网关等待时间。

存储信息

在前端需要临时存储一些用户信息的时候，可以尝试使用==web Storage==这个技术

Web Storage是HTML5内置的前端本地存储技术，无需任何框架、插件

Web Storage分为 session Storage 和 localStorage

它们的区别是：

维度 sessionStorage(会话存储) localStorage(本地存储)
存储有效期 仅当前会话有效（关闭会话或标签页失效） 持久有效（除非手动清除浏览器缓存）
作用域 当前标签页 用域名下所有标签页共享
存储大小 约5mb 约5mb
适用场景 ==临时存储状态== ==持久存储状态（记住登录）==
